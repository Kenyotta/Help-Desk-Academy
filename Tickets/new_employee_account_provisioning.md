\## Learning Objective



Learn the standard workflow for provisioning a new employee account, verifying request accuracy, preventing duplicate accounts, assigning appropriate security groups, and validating successful account creation.

\# Request Summary



HR submitted a request to create a new Active Directory account for Jennifer Torres before her first day of employment. The account needed to be provisioned with department-specific access and group memberships before Monday at 9:00 AM.



\---



\# Business Impact



Proper account provisioning ensures new employees can:



\- Sign into the corporate domain

\- Access departmental resources

\- Connect to the corporate VPN

\- Access engineering code repositories

\- Begin work without onboarding delays



\---

No missing information was identified.

\---



\# Troubleshooting Timeline



1\. Reviewed service request

2\. Verified request completeness

3\. Searched directory for existing account

4\. Confirmed no duplicate account existed

5\. Created new directory account

6\. Assigned Engineering group

7\. Assigned VPN-Users group

8\. Assigned CodeRepo-Access group

9\. Verified account creation

10\. Closed ticket



\---



\# Lessons Learned



\- Always verify service requests before making changes.

\- Prevent duplicate accounts by searching the directory first.

\- Follow the principle of least privilege by assigning only requested access.

\- Verify changes after implementation rather than assuming they succeeded.

\- New hire provisioning directly impacts employee productivity on their first day.

\# Interview Talking Point



This ticket reinforced the importance of following a structured provisioning process rather than simply creating accounts. Before making any changes, I verified the request was complete, confirmed the user did not already exist in the directory, created the account, assigned the required security groups, and validated that all requested access had been applied successfully before closing the ticket.
